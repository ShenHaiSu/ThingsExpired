## 1. 项目概述

### 1.1 项目类型

- **项目类型**：RESTful API 后端服务
- **运行时**：Bun（JavaScript/TypeScript 运行时）
- **通信协议**：仅使用 HTTP 协议
- **HTTPS 说明**：不实现 HTTPS，由 Nginx 负责 HTTPS 卸载
- **数据库**：SQLite（轻量级，无需额外部署）

### 1.2 技术栈

| 组件 | 技术选型 | 说明 |
|------|----------|------|
| 运行时 | Bun 1.1+ | 必须使用最新稳定版 |
| 语言 | TypeScript 5+ | 严格模式，禁止使用 `any` |
| Web 框架 | Hono | 轻量高性能 HTTP 框架 |
| 数据库 | SQLite（Bun 内置） | 使用 Drizzle ORM |
| ORM | Drizzle ORM | TypeScript-first ORM，类型安全 |
| 参数校验 | Zod | TypeScript-first 模式校验 |
| 日志 | Pino | 高性能结构化日志 |
| 配置 | 环境变量 + Bun 内置 | 支持 `.env` 文件 |
| JWT | `jsonwebtoken` / `jose` | Token 认证 |
| 加密 | Bun 内置 `Bun.password` | 密码哈希 |

### 1.3 编码要求

- 严格遵守分层架构
- 高内聚低耦合
- 面向接口编程（TypeScript Interface）
- 配置外置
- 错误统一处理

## 2. 设计原则

### 2.1 核心原则总览

| 序号 | 原则名称 | 描述 |
|------|----------|------|
| 1 | 严格分层 | 请求必须按照固定顺序流经各层 |
| 2 | 禁止越权 | 每一层只做本层的事情 |
| 3 | 面向接口 | 各层之间通过接口依赖 |
| 4 | 配置外置 | 所有配置通过配置文件/环境变量管理 |
| 5 | 错误统一 | 建立统一的错误类型和响应格式 |

### 2.2 详细原则

#### 2.2.1 严格分层原则

```
┌─────────────────────────────────────────────────────────────────┐
│                        HTTP Request                             │
│                     Content-Type: application/json              │
└─────────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
┌─────────────────────────────────────────────────────────────────┐
│                         Router Layer                             │
│  - 注册路由                                                      │
│  - 绑定方法与路径                                                 │
│  - 挂载中间件                                                    │
└─────────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
┌─────────────────────────────────────────────────────────────────┐
│                        Handler Layer                             │
│  - 参数绑定（从 request body 解析 JSON 到结构体）                  │
│  - 参数校验（使用 Zod 进行必填、格式、范围校验）                     │
│  - 调用 Service                                                  │
│  - 返回响应（统一响应格式）                                        │
└─────────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
┌─────────────────────────────────────────────────────────────────┐
│                         Service Layer                            │
│  - 业务逻辑处理                                                  │
│  - 事务控制                                                     │
│  - 组合多个 Repository                                          │
└─────────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
┌─────────────────────────────────────────────────────────────────┐
│                      Repository Layer                            │
│  - 数据库 CRUD 操作                                             │
│  - 复杂查询封装                                                 │
└─────────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
┌─────────────────────────────────────────────────────────────────┐
│                        Model Layer                               │
│  - 数据库模型定义（Drizzle Schema）                               │
│  - DTO 定义（请求参数）                                          │
│  - VO 定义（响应数据）                                           │
└─────────────────────────────────────────────────────────────────┘
```

#### 2.2.2 禁止越权原则

| 层级 | 职责 | 禁止事项 |
|------|------|----------|
| **Router** | 注册路由、绑定方法与路径、挂载中间件 | ❌ 禁止处理业务逻辑 |
| **Handler** | 参数绑定、参数校验、调用 Service、返回响应 | ❌ 禁止业务逻辑<br>❌ 禁止直接操作数据库 |
| **Service** | 业务逻辑处理、事务控制、组合多个 Repository | ❌ 禁止直接操作数据库<br>❌ 禁止处理 HTTP 请求/响应 |
| **Repository** | 数据库 CRUD 操作、复杂查询封装 | ❌ 禁止业务逻辑 |
| **Model** | 定义数据结构 | ❌ 禁止业务逻辑 |

#### 2.2.3 面向接口编程原则

- **定义位置**：接口在调用方所在层定义（Service 接口在 handler 层引用，Repository 接口在 service 层引用）
- **实现位置**：接口实现在被调用方所在层
- **好处**：便于单元测试和替换实现

```typescript
// Handler 层使用 Service 接口（定义在 service 层）
import type { IUserService } from '../service/interfaces';

// Service 层定义接口（供 Handler 层依赖）
export interface IUserService {
  getUserById(ctx: HonoContext, id: number): Promise<UserVO>;
  createUser(ctx: HonoContext, req: CreateUserRequest): Promise<UserVO>;
}

// Service 层实现接口
export class UserService implements IUserService {
  constructor(private userRepo: IUserRepository) {} // 依赖接口而非具体实现

  async getUserById(ctx: HonoContext, id: number): Promise<UserVO> {
    // 实现逻辑
  }
}
```

#### 2.2.4 配置外置原则

- 所有可变配置必须通过配置文件或环境变量管理
- 禁止在代码中硬编码任何配置值（常量除外）
- 支持多环境配置（dev、test、prod）

#### 2.2.5 错误统一处理原则

- 所有错误必须使用自定义错误类型
- 错误响应格式必须统一
- 错误需要区分业务错误和系统错误

## 3. 分层架构

### 3.1 Router Layer

#### 3.1.1 职责

| 职责 | 说明 |
|------|------|
| 注册路由 | 将 URL 路径与方法绑定 |
| 挂载中间件 | 全局中间件、路由组中间件 |
| 路径前缀 | 所有 API 必须以 `/api` 开头 |

#### 3.1.2 实现规范

```typescript
// 位置：src/router/index.ts

import { Hono } from 'hono';
import type { UserHandler } from '../handler/user';
import type { CategoryHandler } from '../handler/category';
import type { ItemHandler } from '../handler/item';
import type { AuthMiddleware } from '../middleware/auth';

export function createRouter(
  userHandler: UserHandler,
  categoryHandler: CategoryHandler,
  itemHandler: ItemHandler,
  authMiddleware: AuthMiddleware,
): Hono {
  const app = new Hono();

  // API 路由组（所有 API 必须以 /api 开头）
  const api = app.basePath('/api');

  // ===== 用户模块（无需认证） =====
  api.post('/user/register', userHandler.register);
  api.post('/user/login', userHandler.login);

  // ===== 用户模块（需认证） =====
  const user = new Hono();
  user.use('*', authMiddleware.handle);
  user.post('/info', userHandler.getInfo);
  user.post('/update', userHandler.update);
  user.post('/logout', userHandler.logout);
  user.post('/sessions', userHandler.getSessions);
  user.post('/revoke_session', userHandler.revokeSession);
  user.post('/force_logout', userHandler.forceLogout);
  api.route('/user', user);

  // ===== 分类模块（需认证） =====
  const category = new Hono();
  category.use('*', authMiddleware.handle);
  category.post('/create', categoryHandler.create);
  category.post('/list', categoryHandler.list);
  category.post('/update', categoryHandler.update);
  category.post('/delete', categoryHandler.delete);
  api.route('/category', category);

  // ===== 物品模块（需认证） =====
  const item = new Hono();
  item.use('*', authMiddleware.handle);
  item.post('/create', itemHandler.create);
  item.post('/list', itemHandler.list);
  item.post('/detail', itemHandler.detail);
  item.post('/update', itemHandler.update);
  item.post('/delete', itemHandler.delete);
  item.post('/expiring', itemHandler.getExpiring);
  item.post('/stats', itemHandler.getStats);
  item.post('/mark_used', itemHandler.markUsed);
  api.route('/item', item);

  return app;
}
```

### 3.2 Handler Layer

#### 3.2.1 职责

| 职责 | 说明 |
|------|------|
| 参数绑定 | 从 request body 解析 JSON 到结构体 |
| 参数校验 | 使用 Zod 进行必填、格式、范围校验 |
| 调用 Service | 调用对应的 Service 方法 |
| 返回响应 | 使用统一响应格式返回结果 |

#### 3.2.2 实现规范

```typescript
// 位置：src/handler/user.ts

import type { Context } from 'hono';
import type { IUserService } from '../service/interfaces';
import { z } from 'zod';
import { success, failWithCode } from '../utils/response';
import { CodeParamInvalid } from '../errors/code';

// Zod 校验模式定义
const getUserInfoSchema = z.object({
  user_id: z.number().min(1, '用户ID必须大于0'),
});

export class UserHandler {
  constructor(private userService: IUserService) {}

  async getInfo(c: Context): Promise<Response> {
    // 1. 参数绑定与校验
    const body = await c.req.json();
    const result = getUserInfoSchema.safeParse(body);
    if (!result.success) {
      return failWithCode(c, CodeParamInvalid, result.error.message);
    }

    // 2. 调用 Service
    const user = await this.userService.getUserById(c, result.data.user_id);

    // 3. 返回成功响应
    return success(c, user);
  }
}
```

### 3.3 Service Layer

#### 3.3.1 职责

| 职责 | 说明 |
|------|------|
| 业务逻辑处理 | 实现所有业务逻辑 |
| 事务控制 | 管理数据库事务 |
| 组合 Repository | 调用多个 Repository 完成复杂业务 |

#### 3.3.2 实现规范

```typescript
// 位置：src/service/user.ts

import type { Context } from 'hono';
import type { IUserRepository } from '../repository/interfaces';
import type { IUserService } from './interfaces';
import type { UserVO } from '../model/vo/user';
import type { CreateUserRequest } from '../model/dto/user';
import { toUserVO } from '../model/vo/user';

export class UserService implements IUserService {
  constructor(
    private userRepo: IUserRepository,
    private sessionRepo: ISessionRepository,
  ) {}

  async getUserById(ctx: Context, id: number): Promise<UserVO> {
    // 1. 调用 Repository 获取数据
    const user = await this.userRepo.findById(id);
    if (!user) {
      throw new AppError(CodeUserNotFound, '用户不存在');
    }

    // 2. 业务逻辑处理
    if (user.status !== 1) {
      throw new AppError(CodeForbidden, '账户已禁用');
    }

    // 3. 转换为 VO
    return toUserVO(user);
  }

  async createUser(ctx: Context, req: CreateUserRequest): Promise<UserVO> {
    // 使用事务
    return await this.userRepo.transaction(async (tx) => {
      // 1. 业务校验
      const exist = await tx.findByEmail(req.email);
      if (exist) {
        throw new AppError(CodeUserExists, '邮箱已被注册');
      }

      // 2. 创建用户
      const hashedPassword = await Bun.password.hash(req.password, {
        algorithm: 'bcrypt',
        cost: 10,
      });

      const user = await tx.create({
        username: req.username,
        email: req.email,
        password: hashedPassword,
        status: 1,
      });

      // 3. 返回 VO
      return toUserVO(user);
    });
  }
}
```

### 3.4 Repository Layer

#### 3.4.1 职责

| 职责 | 说明 |
|------|------|
| 数据库 CRUD | 提供基础增删改查方法 |
| 复杂查询封装 | 提供复杂查询方法 |
| 事务支持 | 支持事务操作 |

#### 3.4.2 实现规范

```typescript
// 位置：src/repository/user.ts

import { eq, and } from 'drizzle-orm';
import type { DBInstance } from './db';
import { users } from '../model/user';
import type { IUserRepository } from './interfaces';

export class UserRepository implements IUserRepository {
  constructor(private db: DBInstance) {}

  async findById(id: number) {
    const result = await this.db
      .select()
      .from(users)
      .where(eq(users.id, id))
      .limit(1);

    return result[0] || null;
  }

  async findByEmail(email: string) {
    const result = await this.db
      .select()
      .from(users)
      .where(eq(users.email, email))
      .limit(1);

    return result[0] || null;
  }

  async create(data: InsertUser) {
    const result = await this.db
      .insert(users)
      .values(data)
      .returning();

    return result[0];
  }

  // 复杂查询封装
  async list(params: { page: number; pageSize: number }) {
    const offset = (params.page - 1) * params.pageSize;
    const items = await this.db
      .select()
      .from(users)
      .limit(params.pageSize)
      .offset(offset);

    const [{ count }] = await this.db
      .select({ count: sql<number>`count(*)` })
      .from(users);

    return { items, total: count };
  }
}
```

### 3.6 后台定时任务规范

后台定时任务属于 **Service 层** 职责，遵循以下规范：

1. 定时任务类作为独立 Service 实现
2. 定义接口（interface）供应用入口调用
3. 使用 `setInterval` 实现定时触发（Bun 不支持 `time.Ticker`，使用标准 JS 定时器替代）
4. 支持启动（`start`）和停止（`stop`）生命周期管理
5. 启动时立即执行一次，之后按间隔执行
6. 使用 `AbortController` 实现优雅停止

```typescript
// 位置：src/service/item_expiration.ts

export interface IItemExpirationService {
  start(): void;
  stop(): void;
  checkExpiredItems(): Promise<number>;
}

export class ItemExpirationService implements IItemExpirationService {
  private intervalId: ReturnType<typeof setInterval> | null = null;
  private abortController: AbortController | null = null;

  constructor(
    private itemRepo: IItemRepository,
    private config: ExpirationConfig,
    private logger: PinoLogger,
  ) {}

  start(): void {
    if (this.intervalId !== null) return;
    if (!this.config.enabled) {
      this.logger.info('过期检查任务已禁用');
      return;
    }

    this.abortController = new AbortController();

    // 启动时先执行一次
    this.checkExpiredItems();

    // 定时触发
    this.intervalId = setInterval(() => {
      this.checkExpiredItems();
    }, this.config.intervalSec * 1000);

    this.logger.info({ intervalSec: this.config.intervalSec, batchSize: this.config.batchSize }, '过期检查任务已启动');
  }

  stop(): void {
    if (this.intervalId !== null) {
      clearInterval(this.intervalId);
      this.intervalId = null;
    }
    if (this.abortController) {
      this.abortController.abort();
      this.abortController = null;
    }
    this.logger.info('过期检查任务已停止');
  }
}
```

## 4. API 规范

### 4.1 基础规范

| 规范 | 要求 | 说明 |
|------|------|------|
| 路径前缀 | `/api` | 所有 API 必须以 `/api` 开头 |

| 请求体格式 | `JSON` | 请求 body 必须为 JSON 格式 |

### 4.2 URL 规范

```
# 标准 API 格式
POST /api/{module}/{resource}

# 示例
POST /api/user/login          # 用户登录
POST /api/user/info           # 获取用户信息
POST /api/category/list       # 分类列表
POST /api/item/create         # 创建物品
```

### 4.3 请求规范

**请求头**：

```typescript
// 位置：src/utils/response.ts

import type { Context } from 'hono';
import { CodeSuccess, CodeInternalError } from '../errors/code';
import { AppError } from '../errors';

interface ResponseBody {
  code: number;
  message: string;
  data: unknown;
}

export function success(c: Context, data: unknown): Response {
  return c.json({
    code: CodeSuccess,
    message: 'success',
    data,
  } satisfies ResponseBody);
}

export function failWithCode(c: Context, code: number, message: string): Response {
  return c.json({
    code,
    message,
    data: null,
  } satisfies ResponseBody);
}

export function fail(c: Context, error: unknown): Response {
  if (error instanceof AppError) {
    return c.json({
      code: error.code,
      message: error.message,
      data: null,
    } satisfies ResponseBody);
  }

  // 未知错误
  console.error('Unhandled error:', error);
  return c.json({
    code: CodeInternalError,
    message: '内部错误',
    data: null,
  } satisfies ResponseBody);
}
```

## 10. 依赖管理

### 10.1 应用入口与依赖组装

采用 **手动依赖注入** 模式，在应用入口处组装所有依赖。

```typescript
// 位置：src/index.ts

import { Hono } from 'hono';
import { loadConfig } from './config';
import { createDB } from './repository/db';
import { UserRepository } from './repository/user';
import { CategoryRepository } from './repository/category';
import { ItemRepository } from './repository/item';
import { SessionRepository } from './repository/session';
import { UserService } from './service/user';
import { CategoryService } from './service/category';
import { ItemService } from './service/item';
import { ItemExpirationService } from './service/item_expiration';
import { UserHandler } from './handler/user';
import { CategoryHandler } from './handler/category';
import { ItemHandler } from './handler/item';
import { AuthMiddleware } from './middleware/auth';
import { createRouter } from './router';
import { createLogger } from './utils/logger';

async function main() {
  // 1. 加载配置
  const config = loadConfig();

  // 2. 创建日志器
  const logger = createLogger(config.app.mode);

  // 3. 初始化数据库
  const db = createDB(config.database);

  // 4. 创建 Repository 实例
  const userRepo = new UserRepository(db);
  const categoryRepo = new CategoryRepository(db);
  const itemRepo = new ItemRepository(db);
  const sessionRepo = new SessionRepository(db);

  // 5. 创建 Service 实例
  const userService = new UserService(userRepo, sessionRepo);
  const categoryService = new CategoryService(categoryRepo);
  const itemService = new ItemService(itemRepo);

  // 6. 创建后台定时任务
  const expirationConfig = {
    enabled: true,
    intervalSec: 3600,
    batchSize: 100,
  };
  const expirationService = new ItemExpirationService(itemRepo, expirationConfig, logger);

  // 7. 创建中间件
  const authMiddleware = new AuthMiddleware(config.jwt, sessionRepo);

  // 8. 创建 Handler 实例
  const userHandler = new UserHandler(userService);
  const categoryHandler = new CategoryHandler(categoryService);
  const itemHandler = new ItemHandler(itemService);

  // 9. 创建路由
  const app = createRouter(userHandler, categoryHandler, itemHandler, authMiddleware);

  // 10. 启动定时任务
  expirationService.start();

  // 11. 启动服务器
  logger.info({ host: config.app.host, port: config.app.port }, '服务器启动中');
  Bun.serve({
    fetch: app.fetch,
    port: config.app.port,
    hostname: config.app.host,
  });

  logger.info({ host: config.app.host, port: config.app.port }, '服务器已启动');

  // 12. 优雅关闭
  process.on('SIGINT', () => {
    logger.info('收到 SIGINT 信号，正在关闭服务...');
    expirationService.stop();
    process.exit(0);
  });
}

main().catch(console.error);
```

### 10.2 生命周期管理原则

1. **启动顺序**：Config → Logger → Database → Repository → Service → Middleware → Handler → Router → Server
2. **关闭顺序**：定时任务 → Server → Database（与启动顺序相反）
3. **禁止循环依赖**：各层之间禁止出现循环依赖，Repository 不可依赖 Service

## 11. 中间件规范

### 11.1 认证中间件

```typescript
// 位置：src/middleware/auth.ts

import type { Context, Next } from 'hono';
import { failWithCode } from '../utils/response';
import { CodeUnauthorized } from '../errors/code';
import type { JWTConfig } from '../config';

export class AuthMiddleware {
  constructor(
    private jwtConfig: JWTConfig,
    private sessionRepo: ISessionRepository,
  ) {}

  async handle(c: Context, next: Next): Promise<Response | void> {
    // 获取 Authorization header
    const authHeader = c.req.header('Authorization');
    if (!authHeader) {
      return failWithCode(c, CodeUnauthorized, '缺少认证信息');
    }

    // 解析 Bearer token
    const token = authHeader.replace('Bearer ', '');
    if (token === authHeader) {
      return failWithCode(c, CodeUnauthorized, 'Token 格式无效');
    }

    try {
      // 验证 token
      const payload = await verifyJWT(token, this.jwtConfig.secret);

      // 验证会话是否有效
      const session = await this.sessionRepo.findByJTI(payload.jti);
      if (!session || session.isRevoked) {
        return failWithCode(c, CodeUnauthorized, '会话已失效');
      }

      // 将用户信息存入 context
      c.set('userId', payload.userId);
      c.set('sessionId', session.id);

      await next();
    } catch (error) {
      return failWithCode(c, CodeUnauthorized, 'Token 无效或已过期');
    }
  }
}
```

```typescript
}, (table) => ({
  emailIdx: uniqueIndex('idx_users_email').on(table.email),
  statusIdx: index('idx_users_status').on(table.status),
}));
```

```typescript
// 位置：test/service/item_expiration.test.ts

import { describe, expect, test, beforeAll, afterAll } from 'bun:test';
import { Database } from 'bun:sqlite';
```

### A. 完整请求流程示例

用户注册流程：

```
1. Client 发送 POST 请求
   POST /api/user/register
   Content-Type: application/json
   Body: {"username": "test", "email": "test@example.com", "password": "123456"}

2. Router 匹配路由，调用 Handler
   Router: api.post('/user/register', userHandler.register)

3. Handler 参数绑定和校验
   - 解析 JSON 到 CreateUserRequest
   - 使用 Zod 校验参数
   - 调用 Service

4. Service 业务逻辑处理
   - 校验邮箱是否已存在
   - 使用 Bun.password.hash 加密密码
   - 调用 Repository 创建用户
   - 返回 UserVO

5. Repository 数据库操作
   - 检查邮箱是否存在
   - 插入用户记录

6. Model 数据结构
   - User Schema 数据库模型
   - CreateUserRequest DTO
   - UserVO 响应数据

7. 逐层返回响应
   Repository → Service → Handler → Router → Client
```
